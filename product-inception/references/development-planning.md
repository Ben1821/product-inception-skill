# Development Planning

- **用價值切片安排順序。** 從 MVP 的旅程和驗收條件回推，先排可端到端展示的工作。高影響未知會左右實作時，先排驗證並註明阻擋哪項工作。依賴以少量連結或 ID 標示。
- **用 INVEST 審視近期故事。** 檢查故事是否能拆到足夠獨立、可協商、有價值、可估、夠小且可驗收。遇到外部依賴，明示影響和驗證順序。技術工作可直接描述要降低的風險與結束條件。
- **交付可檢視的第一輪。** 確認團隊人力與實際可用時間後，再談承諾。容量未知時，交付候選順序、依賴和可展示成果。長期項目留粗粒度，精細化近期工作。
- **流程依團隊運作選擇。** 個人或小團隊可以用排序待辦和短週期檢視。團隊採 Scrum 時，再談 Product Goal、Sprint Goal、開發者選定的 Sprint Backlog、適用的 Definition of Done 與 Review。故事驗收檢查該故事行為，Definition of Done 描述 Increment 要達到的共同品質標準。
